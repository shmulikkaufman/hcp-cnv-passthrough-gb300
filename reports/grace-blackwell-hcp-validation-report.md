## 7. Story 6 — VM-to-VM RDMA + GPUDirect (CX-8 rails)

**Objective:** 4× 400G CX-8 VFs per VM; RoCE RDMA system-memory and GPU-memory at line rate.

**Setup validated:** VF-supply DaemonSet (runtime sysfs, self-healing), cx8-shim device plugin (bridges `PCI_RESOURCE_*`, kernel-6.x vfio cdevs — CNV-91802, per-resource sockets), `pci_bus_guard` hook (disjoint PCIe-expander bus ranges), jumbo MTU (Ethernet 9000 / RDMA 4096, DF-set-verified per rail both directions).

### System-memory RDMA (perftest `ib_write_bw`, 64 KiB, pinned, 4 vCPUs)

| Test | Result | Verdict |
|---|---|---|
| Single-QP per rail, both directions | 383.02–388.74 Gb/s | ✅ |
| Sustained per rail (16 QPs, 30 s) | 390.28 Gb/s (97.6% of 400G) | ✅ line rate |
| 4 rails concurrent, one-way | **1,560.84 Gb/s** — full line rate every rail (390.08–390.28) | ✅ |
| 4 rails concurrent, bidirectional | **~2,656 Gb/s** (NUMA-0 rails 775–778 full-duplex; NUMA-1 525–578) | ✅ (NUMA-1 caveat known) |
| Write latency (2 B × 1,000) | 2.34–2.38 µs (NUMA-0) / 3.15–3.23 µs (NUMA-1) | ✅ |
| Path proof | `rx_write_requests` hardware-counter delta reconciles exactly with reported traffic, per rail | ✅ |

### GPUDirect RDMA (dma-buf; source-built perftest `--use_cuda=0 --use_cuda_dmabuf`)

| Test | Result | Verdict |
|---|---|---|
| Single-QP GPU↔GPU, both directions | 386.10 / 386.21 Gb/s | ✅ |
| Sustained (16 QPs, 30 s) | 390.25 Gb/s — identical to system memory | ✅ |
| Two GPU-local rails concurrent | 780.02 Gb/s | ✅ |
| Four rails, buffers split across both GPUs | **1,560.63 Gb/s** — full line rate every rail | ✅ |
| Four rails, all buffers on one GPU | 1,165.29 Gb/s — single-GPU host-interface bound | ⚠ documented finding, not a defect |
| Buffers on-GPU confirmation | `nvidia-smi`: 682 MiB held by `ib_write_bw` mid-run | ✅ |
| Negative control: peermem path (`--use_cuda` without dmabuf) | fails as expected (MOFED-only kernel API) | ✅ expected |
| **Byte-exact content verification** (`gpudirect-verify.py`: 3 rounds × 32 MiB positional patterns, on-GPU readback) | all rounds `bad_tiles=0/512`, counter delta exactly 96 | ✅ |

**Key findings:** GPU-memory RDMA runs at full rail speed with **no measurable penalty** vs host memory; GPUDirect multi-rail aggregates are bound by GPU host interfaces unless buffers are spread across GPUs (an NCCL-style app does this naturally).

**Defects hit (21 recorded, all resolved or documented):** SR-IOV policy-layer node reboot loop (→ no-policies design + VF-supply DaemonSet), CNV-91802 cdev gap (→ shim), PCIe bus-range collisions (→ guard hook), ARP flux across rails, NetworkManager VF-IP flushing, DAD silence on fresh IPv4, peermem/MOFED API absence (→ dma-buf path), perftest RPM without CUDA (→ source build), memlock limit, pyverbs/ctypes API pitfalls (6, in custom-test development).

## 9. Known limitations (documented, non-blocking)

- **Fabric:** best-effort L2 — no loss observed at line rate, but congestion untested; production RDMA under load requires lossless Ethernet (PFC/ECN or adaptive routing) — pending network team, along with production IPAM/VLAN.
- **Runtime-only settings:** guest test networking and host PF MTU 9000 must be re-applied after worker/guest reboots (boot-time provisioning is a separate task).
- **NUMA-1 bidirectional** throughput settles at 525–578 Gb/s (cross-socket DMA) vs NUMA-0's 775–778.
- **Untested by scope decision:** NCCL-style single-app multi-rail, MOFED/DOCA on the 64 KiB-page guest, dual-plane 800G per GPU (port-1 PFs idle), gdrcopy, bond/LAG/ECMP.
